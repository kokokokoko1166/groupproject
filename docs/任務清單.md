# 任務清單（複製到 GitHub Issues 用）

每一個「## 標題」就是一個 Issue。到 Repo 的 **Issues → New issue**，把標題和下面的內容複製貼上，右邊 **Assignees** 選負責的組員。

標示「不用寫程式」的任務，不會寫程式的組員也能完成。

---

## 【AI 測試】取得金鑰並實測 AI（不用寫程式）
- [ ] 到 Google AI Studio 申請 Gemini API 金鑰
- [ ] 打開網頁 →「⚙ AI 設定」貼上金鑰，按「儲存並測試」，出現 ✅ 截圖
- [ ] 測試「隨手打字」→ AI 整理，記錄 5 個例子（原文、AI 結果、好不好）
- [ ] 自己寫一張假的手寫便條拍照，測試照片辨識
- [ ] 測試「AI 撰寫教師觀察與建議」
- [ ] 發現 AI 寫錯或亂加內容時，開新的 Issue 回報並附截圖
- [ ] 提醒：只能用假資料，金鑰不可以貼到 GitHub

## 【內容與測試】手機實測（不用寫程式）
- [ ] 用手機打開 GitHub Pages 網址
- [ ] 計時：從選學生到送出，能不能在 10 秒內完成
- [ ] 測試語音輸入是否正常
- [ ] 每發現一個問題（看不清楚、按不到、出錯）就開一個 Issue 回報

## 【內容與測試】確認事件類型與正式紀錄格式（不用寫程式）
- [ ] 參考問卷原始回答，確認 6 種事件類型與處理方式是否合適
- [ ] 確認「正式紀錄」的段落與用語是否符合學校習慣
- [ ] 把建議寫成 docs/內容建議.md 上傳

## 【前端】畫面與功能調整
- [ ] 依測試回報的 Issues 修正畫面
- [ ] 紀錄列表加上「修改」功能
- [ ] 加上「匯出成 Excel / CSV」按鈕

## 【後台】建立 Google 試算表
- [ ] 把 docs/試算表範本.xlsx 上傳到 Google 雲端硬碟，轉成 Google 試算表
- [ ] 確認三個工作表：學生名單、事件類型、事件紀錄
- [ ] 擴充功能 → Apps Script，貼上 apps-script/Code.gs
- [ ] 截圖放到 docs/

## 【後台】完成 Apps Script 並串接前端
- [ ] 完成 Code.gs 裡標示 TODO 的部分（讀取紀錄、寫入紀錄）
- [ ] 在「指令碼屬性」設定通行碼 PASSCODE（不可寫在程式碼裡）
- [ ] 部署成網頁應用程式，取得網址
- [ ] 修改 index.html 的「資料存取」區塊，改成呼叫 Apps Script
- [ ] 學生名單、事件類型改成從試算表讀取

## 【文件】一頁說明與報告（不用寫程式）
- [ ] 截圖：Repo 首頁、Collaborators、Commits、Issues、網頁畫面

- [ ] 把問卷分析放進 docs/
